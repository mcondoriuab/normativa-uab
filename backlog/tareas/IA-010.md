# IA-010: Búsqueda híbrida con RRF

## Contexto

BM25 acierta en lo literal y la vectorial en lo coloquial. Queremos las dos,
pero sus puntajes no son comparables (BM25 no tiene tope; el coseno va de -1 a
1). *Reciprocal Rank Fusion* (RRF) las combina usando solo la **posición** de
cada resultado.

## Objetivo

Crear `ia/hibrida.py` con `fusionar_rrf(listas, k=5, K=60)` y una función única
`buscar(pregunta, modo="hibrida", k=5)` que el resto del sistema usará siempre.

## Entradas

- `ia/bm25.py`, `ia/vectorial.py`, `ia/db.py` (`leer_fragmentos`)
- `docs/ARQUITECTURA.md` (sección *Resultado de búsqueda*)

## Pasos sugeridos

1. `fusionar_rrf`: para cada lista y cada resultado en la posición `p`
   (empezando en 1), suma `1 / (K + p)` al `id`. Ordena por la suma y devuelve
   los `k` mejores, con esa suma como `puntaje`.
2. `buscar`: la primera vez que se llama, lee los fragmentos de la base con
   `leer_fragmentos()` y crea el índice BM25; guárdalos en una variable del
   módulo para no repetirlo. Añade una función `cargar()` que haga solo eso
   (la usará BE-004).
3. `modo` puede ser `"bm25"`, `"vectorial"` o `"hibrida"`. Para la híbrida,
   pide a cada búsqueda más candidatos (por ejemplo, 20) antes de fusionar.
4. Incluye en cada resultado híbrido el `puntaje_vectorial` del fragmento
   (`null` si no salió en la vectorial); lo necesitará IA-017 para el umbral.

## Fuera de alcance

- Pesos distintos para cada búsqueda, rerankers.

## Criterios de aceptación

- [ ] `fusionar_rrf` probado a mano: con `[[A, B], [B, C]]`, B queda primero.
- [ ] `buscar` funciona en los tres modos y devuelve el formato del contrato.
- [ ] La segunda llamada no vuelve a leer los fragmentos de la base.

## Cómo verificar

```bash
python -c "
from ia.hibrida import buscar
for modo in ['bm25', 'vectorial', 'hibrida']:
    print(modo, [r['id'] for r in buscar('<pregunta>', modo=modo)])
"
```

## Entregables

- `ia/hibrida.py`

## Para aprender

Fusión de rankings, por qué no se suman puntajes de escalas distintas.
