# BE-008: Supabase: esquema, `ia/db.py` y mantener la base activa

## Contexto

**Tarea de configuración: la hace el docente**, porque usa su cuenta de
Supabase y las credenciales de producción. Al terminar, comparte `DATABASE_URL`
con el equipo **por un canal privado** (paso 7 de `docs/DESPLIEGUE.md`).

Los fragmentos y el registro anónimo de consultas viven en Postgres (Supabase),
porque el disco del servidor de Render se borra en cada reinicio (ADR-002). El
esquema se versiona como **migraciones SQL** en el repo, y todo el acceso desde
Python pasa por un único módulo, `ia/db.py`.

En el plan gratuito, Supabase **pausa el proyecto tras 7 días sin actividad**, y
entonces la API deja de encontrar la base. Por eso un flujo programado la
consulta cada pocos días.

Esta tarea junta las antiguas BE-008 (esquema inicial) y BE-009 (evitar que
Supabase se pause).

## Objetivo

Tener aplicadas las tablas `fragmentos` (sin embedding todavía) y `consultas`,
el módulo `ia/db.py` para guardar y leer fragmentos, `/salud` comprobando la
base y un flujo de GitHub Actions que la mantenga activa.

## Entradas

- `docs/ARQUITECTURA.md`, sección *Base de datos*
- `db/README.md`, `.env.ejemplo`, `docs/DESPLIEGUE.md`
- `apps/api/main.py` y la URL pública de BE-006

## Pasos

### Parte 1: esquema y `ia/db.py`

1. Escribe `db/migraciones/001_inicial.sql`: crea la extensión `vector` y las
   dos tablas del contrato, **excepto** la columna `embedding` (la añade IA-008,
   cuando se conozca la dimensión del modelo).
2. Activa Row Level Security en las dos tablas sin crear políticas: así la API
   pública de Supabase no puede leerlas y solo accede nuestro backend con
   `DATABASE_URL`.
3. Aplícala en el editor SQL de Supabase y anota la fecha en `db/README.md`.
4. Añade `psycopg[binary]` y `python-dotenv` a `requirements.txt`.
5. Crea `ia/db.py` con:
   - `conectar()`: carga `.env` con `python-dotenv` y abre la conexión con
     `DATABASE_URL`; si no existe la variable, lanza un error que diga qué
     falta.
   - `guardar_fragmentos(fragmentos: list[dict])`: *upsert* por `id`.
   - `leer_fragmentos() -> list[dict]`: todos los fragmentos, con las claves
     del contrato.

   Todas las consultas con parámetros (`%s`), nunca concatenando texto.

### Parte 2: mantener la base activa (necesita BE-001 fusionada)

6. En `/salud`, ejecuta `select 1` en la base. Si funciona, devuelve
   `{"estado": "ok", "base_de_datos": "ok"}`; si falla, HTTP 503 con
   `{"estado": "error", "base_de_datos": "error"}`, sin detalles internos.
7. Crea `.github/workflows/mantener-activo.yml` con un `schedule` (cron cada 3
   días) y `workflow_dispatch`, que haga `curl --fail --max-time 120` a la URL
   pública de `/salud`. El tiempo máximo alto es porque Render puede estar
   dormido.
8. Guarda la URL como **variable del repositorio** en GitHub (no escrita en el
   archivo) y configura `DATABASE_URL` en Render (*Environment*), usando la
   cadena **Session pooler**.
9. Lanza el flujo a mano una vez y comprueba que termina en verde. Anota el
   flujo en la tabla de límites de `docs/DESPLIEGUE.md`.

- [ ] Ninguna consulta construye SQL con *f-strings* o `+`.
- [ ] `/salud` en la URL pública informa del estado de la base.

      manual terminó bien.

## Cómo verificar

```bash
python -c "
from ia.db import guardar_fragmentos, leer_fragmentos
f = {'id': 'prueba#art-1', 'documento': 'prueba', 'articulo': '1', 'pagina': 1, 'texto': 'hola'}
guardar_fragmentos([f]); guardar_fragmentos([f])
print([x for x in leer_fragmentos() if x['documento'] == 'prueba'])
"
# y después, en Supabase: delete from fragmentos where documento = 'prueba';
curl -s https://normativa-uab-ldxj.onrender.com/salud
```

y la pestaña *Actions* del repositorio en GitHub.
