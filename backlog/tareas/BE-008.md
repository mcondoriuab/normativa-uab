# BE-008: Esquema inicial de la base de datos

## Contexto

Los fragmentos y el registro anónimo de consultas viven en Postgres (Supabase),
porque el disco del servidor de Render se borra en cada reinicio (ADR-002). El
esquema se versiona como **migraciones SQL** en el repo, y todo el acceso desde
Python pasa por un único módulo, `ia/db.py`.

**Requisito previo:** el docente ha creado el proyecto de Supabase (paso 3 de
`docs/DESPLIEGUE.md`) y te ha pasado `DATABASE_URL` por un canal privado.

## Objetivo

Crear las tablas `fragmentos` (sin embedding todavía) y `consultas`, y el
módulo `ia/db.py` para conectarse, guardar y leer fragmentos.

## Entradas

- `docs/ARQUITECTURA.md` (sección *Base de datos*)
- `db/README.md`, `.env.ejemplo`

## Pasos sugeridos

1. Escribe `db/migraciones/001_inicial.sql` con las dos tablas del contrato,
   **excepto** la columna `embedding` (la añade IA-008, cuando se conozca la
   dimensión del modelo).
2. Activa Row Level Security en las dos tablas sin crear políticas: así la API
   pública de Supabase no puede leerlas y solo accede nuestro backend con
   `DATABASE_URL`.
3. Pide al docente que la aplique en el editor SQL de Supabase y anota la fecha
   en `db/README.md`.
4. Añade `psycopg[binary]` y `python-dotenv` a `requirements.txt`.
5. Crea `ia/db.py` con:
   - `conectar()`: carga `.env` con `python-dotenv` y abre la conexión con
     `DATABASE_URL`; si no existe la variable, lanza un error claro.
   - `guardar_fragmentos(fragmentos: list[dict])`: *upsert* por `id`.
   - `leer_fragmentos() -> list[dict]`: todos los fragmentos, con las claves
     del contrato.
6. Todas las consultas con parámetros, nunca concatenando texto.

## Fuera de alcance

- Embeddings y búsqueda (IA-008, IA-009).
- Guardar consultas (BE-010).

## Criterios de aceptación

- [ ] La migración está aplicada y registrada en `db/README.md`.
- [ ] Guardar 2 fragmentos de prueba y leerlos devuelve lo mismo; guardarlos
      otra vez no los duplica. Después se borran.
- [ ] Sin `DATABASE_URL`, `conectar()` explica qué falta.
- [ ] Ninguna consulta construye SQL con *f-strings* o `+`.

## Cómo verificar

```bash
python -c "
from ia.db import guardar_fragmentos, leer_fragmentos
f = {'id': 'prueba#art-1', 'documento': 'prueba', 'articulo': '1', 'pagina': 1, 'texto': 'hola'}
guardar_fragmentos([f]); guardar_fragmentos([f])
print([x for x in leer_fragmentos() if x['documento'] == 'prueba'])
"
# y después: delete from fragmentos where documento = 'prueba';
```
