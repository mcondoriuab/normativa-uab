# IA-009: Búsqueda vectorial con pgvector

## Contexto

Con los embeddings guardados en Supabase, buscar es calcular el embedding de la
pregunta y pedirle a Postgres los fragmentos más cercanos. pgvector lo hace con
el operador `<=>` (distancia coseno): una consulta SQL que todo el equipo puede
leer.

## Objetivo

Crear `ia/vectorial.py` con `buscar_vectorial(pregunta: str, k: int = 5)`, que
devuelve resultados con el formato del contrato.

## Entradas

- `ia/embeddings.py` (`codificar_pregunta`), `ia/db.py` (`conectar`)
- `docs/ARQUITECTURA.md` (*Base de datos* y *Resultado de búsqueda*)

## Pasos sugeridos

1. `vector = codificar_pregunta(pregunta)`.
2. Consulta con parámetros (nunca concatenando texto en el SQL):
   ```sql
   select id, documento, articulo, pagina, texto,
          1 - (embedding <=> %(v)s::vector) as puntaje
   from fragmentos
   order by embedding <=> %(v)s::vector
   limit %(k)s
   ```
   Pasa el vector como texto con el formato `'[0.1,0.2,...]'`.
3. Convierte cada fila a `{"id", "puntaje", "fragmento": {...}}`.

## Fuera de alcance

- Índices aproximados (HNSW, IVFFlat): con unos miles de filas no hacen falta.
- Combinar con BM25 (IA-010).

## Criterios de aceptación

- [ ] Devuelve `k` resultados ordenados de mayor a menor puntaje.
- [ ] Los puntajes están entre -1 y 1.
- [ ] La consulta usa parámetros, no *f-strings*.
- [ ] Con una pregunta `coloquial` del golden set, el artículo esperado sale en
      el top-5 (si no, anótalo: es un dato útil para IA-013).

## Cómo verificar

```bash
python -c "
from ia.vectorial import buscar_vectorial
for r in buscar_vectorial('<pregunta coloquial>'):
    print(round(r['puntaje'], 3), r['id'])
"
```
