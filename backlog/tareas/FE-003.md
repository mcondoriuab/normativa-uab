# FE-003: Interfaz completa: respuesta, citas, estados y accesibilidad

## Contexto

La página ya existe (FE-001) y la API la sirve con un `/preguntar` simulado
(BE-002). Falta que el formulario envíe la pregunta de verdad y muestre lo que
responde la API, con citas que se puedan desplegar, estados claros (cargando,
respuesta, rechazo y error) y una accesibilidad básica revisada.

Todo se hace contra el **mock** de BE-002, que ya cumple el contrato. Cuando el
motor real esté conectado (BE-003), la web no tiene que cambiar.

Esta tarea junta las antiguas FE-003 (enviar y mostrar), FE-004 (citas
desplegables), FE-005 (estados) y FE-006 (accesibilidad).

## Objetivo

Crear `apps/web/app.js` para que la página llame a `POST /preguntar`, muestre la
respuesta y las citas desplegables y los cuatro estados, y que la página
obtenga al menos 90 en accesibilidad en Lighthouse.

## Entradas

- `apps/web/index.html`, `apps/web/estilos.css` (FE-001)
- `docs/ARQUITECTURA.md`, sección *API* (campos de la respuesta, `rechazada`,
  HTTP 422)
- La API en marcha: `uvicorn apps.api.main:app --reload` y abrir
  `http://localhost:8000/`. Con la palabra `rechazo` en la pregunta, el mock
  devuelve un rechazo.
- `AGENTS.md`, sección *Estilo del código* (seguridad: `textContent`).

## Regla de seguridad (léela antes de empezar)

**Nunca uses `innerHTML`** con texto que venga de la API: lo escribió un modelo
y podría contener HTML o un `<script>` (eso se llama XSS). Crea los elementos
con `document.createElement(...)` y pon el texto con `.textContent = ...`.

## Pasos

### Parte 1: enviar la pregunta y mostrar la respuesta

1. En `apps/web/index.html`, borra el contenido de ejemplo fijo de
   `<section id="respuesta">` (deja la sección vacía) y comprueba que el
   `<script src="app.js" defer>` sigue ahí.
2. En `apps/web/app.js`, escucha el evento `submit` de `#formulario` y llama a
   `evento.preventDefault()`.
3. Llama a la API con `async/await`:

   ```js
   const respuesta = await fetch("/preguntar", {
     method: "POST",
     headers: { "Content-Type": "application/json" },
     body: JSON.stringify({ pregunta: textoPregunta }),
   });
   ```

4. Antes de pintar, vacía la sección de respuesta
   (`seccion.replaceChildren()`) para que una segunda pregunta **reemplace** la
   anterior en vez de añadirse.
5. Pinta un `<p>` con `datos.respuesta` y, debajo, la lista de citas (Parte 2).

### Parte 2: citas desplegables

6. Cada cita es un `<details>` con un `<summary>` dentro. No necesitan
   JavaScript para abrirse y cerrarse, y funcionan con teclado.
7. El texto del `<summary>` sigue este formato:
   `[n] documento · Art. X · pág. Y`. Si `articulo` es `null`, quita la parte
   `· Art. X`: `[n] documento · pág. Y`.
8. Dentro del `<details>`, un `<p>` con el texto completo de la cita. En
   `estilos.css`, dale `white-space: pre-line` para respetar los saltos de
   línea.
9. Las citas empiezan cerradas (sin el atributo `open`).

### Parte 3: los cuatro estados

10. **Cargando:** al enviar, desactiva el botón (`boton.disabled = true`) y
    cambia su texto a `Buscando…`.
11. **Servidor despertando:** en el plan gratuito de Render, la primera
    petición tras un rato sin uso tarda hasta un minuto. Con
    `setTimeout(..., 5000)`, si la respuesta no ha llegado en 5 segundos,
    muestra: `El servidor está despertando, puede tardar hasta un minuto.`
    Cancélalo con `clearTimeout` cuando llegue la respuesta.
12. **Rechazo** (`datos.rechazada === true`): muestra la respuesta con un
    estilo neutro, no de error (por ejemplo, la clase `rechazo` con borde
    gris), y la frase `Te sugerimos consultar en secretaría de carrera.` Sin
    citas.
13. **Error:** si `fetch` lanza una excepción o `respuesta.ok` es `false`,
    muestra `No se pudo obtener respuesta. Inténtalo de nuevo.` (clase
    `error`), nunca el error técnico.
14. Usa `try { ... } catch { ... } finally { ... }`. En el `finally`, vuelve a
    activar el botón, restaura su texto `Preguntar` y cancela el temporizador.

### Parte 4: accesibilidad

15. Ejecuta Lighthouse (pestaña *Lighthouse* de Chrome) en modo móvil,
    categoría *Accesibilidad*, y anota la puntuación inicial.
16. Añade `aria-live="polite"` a `<section id="respuesta">` para que el lector
    de pantalla anuncie la respuesta cuando llega.
17. Comprueba que todo se puede usar solo con teclado: Tab hasta el
    `textarea`, escribir, Tab hasta el botón, Enter y Tab hasta una cita y
    Enter para abrirla. El foco tiene que verse siempre: si no se ve, añade en
    el CSS `:focus-visible { outline: 3px solid var(--acento); }`.
18. Comprueba el contraste de los estados de rechazo y de error con
    https://webaim.org/resources/contrastchecker/ (≥ 4.5:1).
19. Corrige lo que marque Lighthouse y vuelve a medir. Anota en el PR la
    puntuación de antes y la de después.

## Fuera de alcance

- Resaltar dentro de la respuesta el `[n]` de cada cita.
- Reintentos automáticos o *timeouts* configurables.
- Auditoría WCAG completa.
- Librerías externas.

## Criterios de aceptación

- [ ] Al preguntar, aparece la respuesta del mock y sus 2 citas.
- [ ] Una segunda pregunta reemplaza la respuesta anterior.
- [ ] Las citas empiezan cerradas, se abren con clic o con Enter y su cabecera
      sigue el formato `[n] documento · Art. X · pág. Y`.
- [ ] Durante la petición no se puede enviar otra.
- [ ] Si tarda más de 5 s, aparece el aviso de servidor despertando.
- [ ] Una pregunta con la palabra `rechazo` muestra el estado de rechazo.
- [ ] Con la API apagada, se ve el mensaje de error y el botón vuelve a
      funcionar.
- [ ] Lighthouse Accesibilidad ≥ 90 (antes y después anotados en el PR).
- [ ] `grep innerHTML apps/web/app.js` no encuentra nada.

## Cómo verificar

```bash
uvicorn apps.api.main:app --reload
grep innerHTML apps/web/app.js        # no debe mostrar nada
```

En `http://localhost:8000/`: pregunta dos veces, pregunta algo con `rechazo`,
abre y cierra citas con el ratón y con Enter, y para `uvicorn` para ver el
error. La consola del navegador no debe mostrar errores. Adjunta capturas de
los cuatro estados al PR.
