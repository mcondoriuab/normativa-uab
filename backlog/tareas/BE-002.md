# BE-002: `/preguntar` simulado y la web servida desde la API

## Contexto

El motor de IA no existirá hasta la segunda semana, pero la web puede
avanzar ya si la API devuelve una respuesta **simulada (mock)** con la forma
exacta del contrato. Cuando el motor esté listo (BE-003), solo cambia el
interior de la ruta; la web no se entera.

Además, si la web se abre con doble clic (`file://`) y llama a
`localhost:8000`, el navegador bloquea la petición por **CORS**. La solución
más simple es que la propia API sirva los archivos de `apps/web/`: así web y
API tienen el mismo origen y no hace falta configurar CORS.

Esta tarea junta las antiguas BE-002 (`/preguntar` simulado) y BE-005 (servir
la web desde la API).

## Objetivo

Que `POST /preguntar` valide la entrada y devuelva una respuesta simulada con la
forma exacta del contrato, y que `http://localhost:8000/` muestre la web de
`apps/web/` sin romper `/salud`, `/preguntar` ni `/docs`.

## Entradas

- `apps/api/main.py` (BE-001: la app FastAPI con `/salud`)
- `apps/web/index.html` y `apps/web/estilos.css` (FE-001)
- `docs/ARQUITECTURA.md`, sección *API* (petición, respuesta y errores)

## Pasos

### Parte 1: `POST /preguntar` con respuesta simulada

1. En `apps/api/main.py`, define con Pydantic estos modelos:

   ```python
   class Peticion(BaseModel):
       pregunta: str = Field(min_length=1, max_length=500)

   class Cita(BaseModel):
       n: int
       documento: str
       articulo: str | None
       pagina: int
       texto: str

   class Respuesta(BaseModel):
       respuesta: str
       rechazada: bool
       citas: list[Cita]
       aviso: str
   ```

2. Define la constante
   `AVISO = "Herramienta de apoyo. El texto oficial y vinculante es el publicado por la universidad."`
3. Crea la ruta `@app.post("/preguntar", response_model=Respuesta)`. Con
   `Field(min_length=1, max_length=500)`, FastAPI ya devuelve **HTTP 422** si la
   pregunta está vacía o es demasiado larga; no escribas esa validación a mano.
4. La ruta devuelve siempre la misma respuesta de ejemplo: un texto con `[1]` y
   `[2]`, `rechazada: False`, 2 citas con `documento: "ejemplo"` y
   `texto: "(respuesta simulada)"`, y `aviso: AVISO`.
5. **Caso de rechazo:** si la pregunta contiene la palabra `rechazo`, devuelve
   `rechazada: True`, `citas: []` y una `respuesta` que diga que no se encontró
   la información en la normativa. Sirve para que la web pruebe ese estado
   (FE-003).

### Parte 2: servir la web desde la API

6. Construye la ruta a `apps/web` a partir de `__file__`, para que funcione
   desde cualquier directorio:

   ```python
   CARPETA_WEB = Path(__file__).resolve().parent.parent / "web"
   ```

7. **Al final del archivo**, después de declarar todas las rutas de la API,
   monta los archivos estáticos:

   ```python
   app.mount("/", StaticFiles(directory=CARPETA_WEB, html=True), name="web")
   ```

   Si lo pones antes de las rutas, tapa `/salud` y `/preguntar`.

## Fuera de alcance

- Buscar en la normativa o llamar a un LLM (BE-003).
- Configurar CORS.
- `app.js`: la web todavía no llama a la API (FE-003).

## Criterios de aceptación

- [ ] La respuesta de `/preguntar` tiene exactamente los campos del contrato.
- [ ] Pregunta vacía o de más de 500 caracteres → HTTP 422.
- [ ] Una pregunta con la palabra `rechazo` devuelve `rechazada: true` y
      `citas: []`.
- [ ] `/docs` muestra los modelos de petición y respuesta.
- [ ] `http://localhost:8000/` muestra la página con estilos.
- [ ] `/salud`, `/preguntar` y `/docs` siguen funcionando con la web montada.

## Cómo verificar

```bash
uvicorn apps.api.main:app --reload
# en otra terminal:
curl -s -X POST localhost:8000/preguntar -H 'Content-Type: application/json' \
     -d '{"pregunta": "cuántas faltas puedo tener"}'
curl -s -X POST localhost:8000/preguntar -H 'Content-Type: application/json' \
     -d '{"pregunta": "prueba de rechazo"}'                         # rechazada: true
curl -s -o /dev/null -w '%{http_code}\n' -X POST localhost:8000/preguntar \
     -H 'Content-Type: application/json' -d '{"pregunta": ""}'      # 422
curl -s localhost:8000/ | head -5                                   # el HTML
curl -s localhost:8000/salud                                        # {"estado":"ok"}
```
