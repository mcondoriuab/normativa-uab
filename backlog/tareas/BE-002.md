# BE-002: /preguntar con respuesta simulada

## Contexto

El motor de IA tardará semanas en existir, pero el frontend puede empezar ya si
la API devuelve una respuesta **simulada (mock)** con la forma exacta del
contrato. Cuando el motor esté listo (BE-003), solo cambia el interior de la
ruta; la web no se entera.

## Objetivo

Añadir `POST /preguntar` que valide la entrada y devuelva una respuesta falsa
con la forma exacta del contrato.

## Entradas

- `apps/api/main.py`
- `docs/ARQUITECTURA.md` (sección *API*: petición, respuesta y errores)

## Pasos sugeridos

1. Define con Pydantic el modelo de la petición: `pregunta` de tipo `str`,
   entre 1 y 500 caracteres (`Field(min_length=1, max_length=500)`).
2. Define los modelos de la respuesta (`Cita` y `Respuesta`) con los campos del
   contrato.
3. La ruta devuelve siempre la misma respuesta de ejemplo con 2 citas
   inventadas y claramente marcadas: documento `"ejemplo"`, texto
   `"(respuesta simulada)"`.
4. **Caso de rechazo:** si la pregunta contiene la palabra `rechazo`, devuelve
   `rechazada: true` y `citas: []`. Sirve para que el frontend pruebe ese
   estado (FE-005).

## Fuera de alcance

- Buscar en la normativa o llamar a un LLM (BE-003).

## Criterios de aceptación

- [ ] La respuesta tiene exactamente los campos del contrato.
- [ ] Pregunta vacía o de más de 500 caracteres → HTTP 422.
- [ ] Una pregunta con la palabra `rechazo` devuelve `rechazada: true`.
- [ ] `/docs` muestra los modelos de petición y respuesta.

## Cómo verificar

```bash
curl -s -X POST localhost:8000/preguntar -H 'Content-Type: application/json' \
     -d '{"pregunta": "cuántas faltas puedo tener"}'
curl -s -o /dev/null -w '%{http_code}\n' -X POST localhost:8000/preguntar \
     -H 'Content-Type: application/json' -d '{"pregunta": ""}'        # 422
```

## Entregables

- `apps/api/main.py`

## Para aprender

Contrato de API, mocks, validación con Pydantic, códigos HTTP 200 y 422.
