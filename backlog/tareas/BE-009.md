# BE-009: Evitar que Supabase se pause

## Contexto

En el plan gratuito, Supabase pausa el proyecto tras 7 días sin actividad, y
entonces la API deja de encontrar la base. Durante vacaciones o semanas sin
uso pasaría seguro. Solución barata: que algo consulte la base cada pocos días.

## Objetivo

Que `/salud` compruebe también la base de datos y que un flujo programado de
GitHub Actions la llame cada 3 días.

## Entradas

- `apps/api/main.py`, `ia/db.py`
- `docs/DESPLIEGUE.md` (sección de límites)

## Pasos sugeridos

1. En `/salud`, ejecuta `select 1` en la base. Si funciona, devuelve
   `{"estado": "ok", "base_de_datos": "ok"}`; si falla, HTTP 503 con
   `"base_de_datos": "error"` (sin detalles internos).
2. Crea `.github/workflows/mantener-activo.yml` con un `schedule` (cron cada 3
   días) y `workflow_dispatch` (para lanzarlo a mano), que haga
   `curl --fail --max-time 120` a la URL pública de `/salud`. El tiempo
   máximo alto es porque Render puede estar dormido.
3. Guarda la URL como variable del repositorio en GitHub, no escrita en el
   archivo.
4. Lánzalo a mano una vez y comprueba que termina en verde.

## Fuera de alcance

- Monitorización o alertas más allá de que el flujo falle en GitHub.

## Criterios de aceptación

- [ ] `/salud` informa del estado de la base.
- [ ] El flujo existe, tiene `schedule` y `workflow_dispatch`, y su primera
      ejecución manual terminó bien.
- [ ] Anotado en `docs/DESPLIEGUE.md`.

## Cómo verificar

```bash
curl -s https://<servicio>.onrender.com/salud
```

y la pestaña *Actions* del repositorio en GitHub.

## Entregables

- `apps/api/main.py`
- `.github/workflows/mantener-activo.yml`
- `docs/DESPLIEGUE.md`

## Para aprender

Tareas programadas (cron), comprobaciones de salud, límites de los planes
gratuitos.

## Notas de cierre

_Qué aprendí · qué falló · en qué usé IA · cuánto tardé._
