# SET-004: Guía de git para el equipo

## Contexto

Todo el equipo va a trabajar con ramas y pull requests (ver `CONTRIBUTING.md`).
Para la mayoría será la primera vez. Una chuleta propia, en español y con
nuestros ejemplos, ahorra muchas consultas repetidas y es lo primero que leerá
cada persona nueva.

## Objetivo

Escribir `docs/GIT.md`: los comandos exactos de nuestro flujo y cómo salir de
los tres problemas más frecuentes.

## Entradas

- `CONTRIBUTING.md` (el flujo de trabajo)

## Pasos sugeridos

1. Configuración inicial: `git config --global user.name` y `user.email`, y
   cómo autenticarse en GitHub (HTTPS con el navegador o SSH).
2. El flujo de una tarea con comandos reales: actualizar `main`, crear la rama
   `SET-004-guia-git`, `add`, `commit`, `push` y abrir el PR.
3. Tres problemas con su solución, **probados por ti** en un repositorio de
   práctica:
   - "Me olvidé de crear la rama y trabajé en `main`."
   - "Mi rama está desactualizada respecto a `main`."
   - "Tengo un conflicto al hacer merge."
4. Una sección "Lo que nunca hay que hacer": `push --force` a `main`, subir
   `.env` o PDFs.

## Fuera de alcance

- Rebase interactivo, submódulos, hooks.

## Criterios de aceptación

- [ ] `docs/GIT.md` cubre la configuración, el flujo y los 3 problemas.
- [ ] Cada comando fue probado (anota en *Notas de cierre* cómo lo probaste).
- [ ] Otro integrante lo usó para su primer PR (SET-002) y dio su opinión.

## Cómo verificar

Un compañero hace su primer PR siguiendo solo `docs/GIT.md`.

## Entregables

- `docs/GIT.md`

## Para aprender

Control de versiones, ramas, merge y conflictos.
