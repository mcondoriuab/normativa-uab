# IA-001: Golden set v0

## Contexto

El golden set es el examen del sistema: preguntas cuya respuesta correcta
conocemos. Sin él, "funciona bien" es una opinión. Se construye **antes** de
tener búsqueda, para que no lo diseñemos a la medida de lo que ya funciona.

## Objetivo

Crear `eval/preguntas.jsonl` con 20 preguntas etiquetadas, incluidas 5 que el
sistema debe rechazar.

## Entradas

- `investigacion/INV-007-preguntas-reales.md`
- PDFs en `corpus/ingenieria-sistemas/`
- `docs/ARQUITECTURA.md` (sección *Golden set*) y `docs/EVALUACION.md`

## Pasos sugeridos

1. Elige 15 preguntas de INV-007 que la normativa sí responda. Busca a mano en
   los PDF el artículo que las responde.
2. Reparte los tipos: al menos 5 `literal`, 5 `coloquial` y 2 `multi-articulo`.
3. Añade 5 `fuera-de-corpus`: preguntas plausibles que la normativa **no**
   responde (sobre la universidad o sobre otros temas).
4. Escribe una línea JSON por pregunta con el formato del contrato. El
   `id_esperado` sigue la convención de fragmentos: `nombre-del-pdf#art-N`.
   Para `multi-articulo`, pon el artículo principal y anota el segundo en
   `respuesta_esperada`.
5. Otra persona revisa 5 líneas al azar contra el PDF.

## Fuera de alcance

- Escribir el script de evaluación (IA-012).

## Criterios de aceptación

- [ ] 20 líneas, todas JSON válido con los 5 campos del contrato.
- [ ] Tipos: ≥5 literal, ≥5 coloquial, ≥2 multi-articulo, 5 fuera-de-corpus.
- [ ] Cada `id_esperado` apunta a un artículo que existe en un PDF del corpus.
- [ ] Revisión cruzada hecha y anotada en *Notas de cierre*.

## Cómo verificar

```bash
python -c "
import json
filas = [json.loads(l) for l in open('eval/preguntas.jsonl', encoding='utf-8')]
print(len(filas), 'preguntas')
from collections import Counter
print(Counter(f['tipo'] for f in filas))
"
```
