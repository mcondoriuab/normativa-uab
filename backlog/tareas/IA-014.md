# IA-014: Capa llm.py

## Contexto

Ningún otro archivo del sistema debe saber qué modelo de lenguaje hay detrás.
Todo pasa por una sola función. Así, cambiar de proveedor (por presupuesto o por
calidad) es tocar un solo archivo.

## Objetivo

Crear `ia/llm.py` con `generar(sistema: str, mensaje: str) -> str`, implementada
con el proveedor elegido en el ADR de INV-010.

## Entradas

- ADR del proveedor de LLM (INV-010)
- Documentación oficial del SDK o de la API del proveedor

## Pasos sugeridos

1. Añade al `requirements.txt` el SDK del proveedor (o nada, si es Ollama por
   HTTP con `urllib`/`requests`).
2. Lee la clave y el modelo de las variables de entorno `LLM_API_KEY` y
   `NORMATIVA_LLM_MODELO` (ya están en `.env.ejemplo`; si el proveedor necesita
   alguna más, añádela allí **sin valores reales**).
3. Llama al modelo con `temperatura = 0`: en normativa queremos respuestas
   repetibles, no creativas.
4. Devuelve solo el texto de la respuesta.
5. Si falta la variable de entorno, lanza un error con un mensaje claro que diga
   qué hay que configurar.

## Fuera de alcance

- Soportar varios proveedores a la vez: se añade otro solo cuando haga falta.
- Reintentos, *streaming*.

## Criterios de aceptación

- [ ] `generar("Responde solo 'hola'.", "Saluda")` devuelve texto.
- [ ] Ninguna clave aparece en el código ni en git.
- [ ] `.env.ejemplo` lista todas las variables necesarias.
- [ ] Temperatura 0.

## Cómo verificar

```bash
python -c "from ia.llm import generar; print(generar('Responde en una frase.', '¿Qué es un reglamento?'))"
git grep -n -i "sk-\|api_key *=" -- ia/        # no debe mostrar claves
```

## Entregables

- `ia/llm.py`
- `.env.ejemplo`
- `requirements.txt`
