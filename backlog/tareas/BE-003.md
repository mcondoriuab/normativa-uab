# BE-003: Motor real en la API: carga al arrancar y registro anónimo

## Contexto

La web ya funciona contra el mock de BE-002. Como `responder()` (IA-016)
devuelve la misma forma que el contrato, conectar el motor real debería ser
cambiar muy pocas líneas. Si hace falta cambiar mucho, algo del contrato no se
respetó.

Leer todos los fragmentos de Supabase y construir el índice BM25 tarda unos
segundos. Si se hace en la primera pregunta, el primer usuario espera mucho más
que el resto, así que se hace **al arrancar el servidor**.

Saber qué pregunta la gente de verdad sirve para ampliar el golden set y
encontrar fallos. Pero las preguntas sobre normativa son sensibles
(`docs/ETICA.md`): se guardan **sin nada que identifique** a quien pregunta, y
se avisa en la interfaz.

Es una tarea del **camino crítico**: BE-007 la despliega el 17 de noviembre.
Puedes hacer la Parte 3 (registro de consultas) en cuanto BE-008 esté cerrada,
antes de que exista `responder()`.

Esta tarea junta las antiguas BE-003 (conectar `/preguntar` al motor real),
BE-004 (cargar el índice una sola vez) y BE-010 (registro anónimo de
consultas).

## Objetivo

Que `POST /preguntar` responda con `ia.responder.responder`, que la API cargue
fragmentos e índice al arrancar, y que cada consulta se guarde de forma anónima
en la tabla `consultas` sin que un fallo al guardar rompa la respuesta.

## Entradas

- `apps/api/main.py` (BE-002 y BE-008)
- `ia/responder.py` (IA-016), `ia/hibrida.py` (función `cargar`, IA-007)
- `ia/db.py` (BE-008)
- `docs/ARQUITECTURA.md` (tabla `consultas`), `docs/ETICA.md`
- `apps/web/index.html`
- Documentación oficial de FastAPI sobre `lifespan`

## Pasos

### Parte 1: conectar el motor real

1. En `apps/api/main.py`, importa `responder` de `ia.responder` y llámalo
   dentro de la ruta con `peticion.pregunta`. Devuelve lo que devuelve.
2. Borra el código del mock, incluido el caso especial de la palabra `rechazo`.
3. Rodea la llamada con `try/except Exception`. Si `responder` lanza una
   excepción (por ejemplo, el LLM no responde), registra el error con
   `logging.exception(...)` y devuelve **HTTP 503** con un mensaje genérico
   (`raise HTTPException(status_code=503, detail="El asistente no está disponible. Inténtalo más tarde.")`).
   Nunca devuelvas el error interno al usuario.

### Parte 2: cargar el índice al arrancar

4. Usa el mecanismo `lifespan` de FastAPI (consulta su documentación actual):
   una función `async` con `@asynccontextmanager` que se pasa a
   `FastAPI(lifespan=...)`.
5. Dentro, antes del `yield`, llama a `ia.hibrida.cargar()` y registra en el
   log cuánto tardó (`time.perf_counter()` antes y después).
6. Mide con `time curl ...` la primera y la segunda pregunta, antes y después
   del cambio, y anota los cuatro tiempos en el PR.

### Parte 3: registro anónimo de consultas

7. Añade a `ia/db.py`:

   ```python
   def guardar_consulta(pregunta: str, rechazada: bool, ids_citados: list[str], latencia_ms: int) -> None:
   ```

   Con un `insert` con parámetros (`%s`), nunca concatenando texto.
8. En `/preguntar`, mide la latencia (`time.perf_counter()`) y, después de
   obtener la respuesta, llama a `guardar_consulta`. Los `ids_citados` son
   `f"{c['documento']}#art-{c['articulo']}"` de cada cita, o
   `f"{c['documento']}"` si `articulo` es `None`.
9. Rodea `guardar_consulta` con su propio `try/except`: **si guardar falla, el
   usuario igual recibe su respuesta**. Registra el error en el log y sigue.
10. No guardes IP, *user-agent*, cookies ni ningún otro dato de la petición.
11. En `apps/web/index.html`, junto al aviso legal, añade:
    `Las preguntas se guardan de forma anónima para mejorar el asistente.`

## Fuera de alcance

- Cachés de respuestas o varios procesos.
- El arranque en frío de Render (el servidor dormido): no se arregla aquí.
- Paneles o informes sobre las consultas y borrado automático de registros.

## Criterios de aceptación

- [ ] Una pregunta del golden set devuelve una respuesta real con citas reales.
- [ ] No queda código del mock.
- [ ] Con el LLM mal configurado (borra `LLM_API_KEY` de tu `.env` para
      probarlo), la API responde 503 y no se cae.
- [ ] El log de arranque indica que el índice se cargó y cuánto tardó, y la
      primera pregunta ya no es notablemente más lenta que la segunda.
- [ ] Cada pregunta crea una fila en `consultas` con los campos del contrato y
      ningún dato de la persona.
- [ ] Con la base caída (pon una `DATABASE_URL` incorrecta después de
      arrancar), `/preguntar` sigue respondiendo.
- [ ] El aviso de registro anónimo aparece en la web y la web funciona sin
      otros cambios.

## Cómo verificar

```bash
uvicorn apps.api.main:app
time curl -s -X POST localhost:8000/preguntar -H 'Content-Type: application/json' \
     -d '{"pregunta": "<pregunta del golden set>"}'
python -c "
from ia.db import conectar
with conectar() as c:
    print(c.execute('select * from consultas order by id desc limit 1').fetchone())
"
```

## Para aprender

Por qué los contratos permiten sustituir piezas; errores internos frente a
mensajes al usuario. Ciclo de vida de un servidor y latencia de arranque.
Privacidad por diseño, minimización de datos y fallos que no deben romper la
respuesta principal.
