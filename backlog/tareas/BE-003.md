# BE-003: Conectar /preguntar al motor real

## Contexto

La web ya funciona contra el mock de BE-002. Como `responder()` devuelve la
misma forma que el contrato, conectar el motor real debería ser cambiar muy
pocas líneas. Si hace falta cambiar mucho, algo del contrato no se respetó.

## Objetivo

Que `POST /preguntar` llame a `ia.responder.responder` en vez de devolver el
mock.

## Entradas

- `apps/api/main.py`
- `ia/responder.py`

## Pasos sugeridos

1. Importa `responder` y llámalo dentro de la ruta con `peticion.pregunta`.
2. Elimina el código del mock (incluido el caso especial de la palabra
   `rechazo`).
3. Si `responder` lanza una excepción (por ejemplo, el LLM no responde),
   devuelve HTTP 503 con un mensaje genérico y registra el error en consola.
   Nunca devuelvas el error interno al usuario.

## Fuera de alcance

- Optimizar la carga del índice (BE-004).

## Criterios de aceptación

- [ ] Una pregunta del golden set devuelve una respuesta real con citas reales.
- [ ] No queda código del mock.
- [ ] Con el LLM mal configurado, la API responde 503 y no se cae.
- [ ] La web funciona sin cambios.

## Cómo verificar

```bash
curl -s -X POST localhost:8000/preguntar -H 'Content-Type: application/json' \
     -d '{"pregunta": "<pregunta del golden set>"}'
```

## Entregables

- `apps/api/main.py`

## Para aprender

Por qué los contratos permiten sustituir piezas; errores internos vs mensajes
al usuario.
